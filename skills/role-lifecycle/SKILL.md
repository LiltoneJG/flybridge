# Role lifecycle

Use this skill in every Flybridge role. The durable coordinator owns normal orchestrated progression and approved delivery; lifecycle mutation remains outside role agents.

1. Do not run `flybridge workflow complete`, `fail`, `cancel`, `handoff`, `advance`, or `proceed`.
2. A `single` role does not write a workflow artifact and does not run `workflow role-ready`; those commands are orchestrated-only. Commit required work, run local verification, push once from this worktree, report the result or blocker, then stop. Do not run `workflow complete`.
3. For an orchestrated role, store exactly the role-owned durable artifact: manager `plan`, worker `verification`, or reviewer `review`. Use `workflow artifact put`; never place plan, handoff, status, review, or coordination documents in the implementation repository.
4. A manager leaves the repository at its starting commit and does not push. The coordinator pushes from the manager worktree after every reviewer approves the same SHA. A worker commits all implementation needed by review, never pushes, and leaves no unrelated changes. A reviewer reviews committed history, records `approved` or `changes-requested`, and never pushes.
5. When all required evidence exists, run `workflow role-ready` with a one-line summary; a reviewer also supplies `--outcome`. This command records an idempotent readiness event and does not close the role terminal.
6. If required input, access, environment, or verification is unavailable, store the required role artifact documenting verified and unverified scope, then run `workflow role-ready ID --summary ONE_LINE --outcome blocked`. Repository-state gates still apply. Waiting on a Flybridge queue resource is not a blocker: report the request-id, remain parked, and resume after the lease-id arrives. After the grant, hold the lease through operation-specific cleanup and confirmation that the next holder will not be affected, then run `queue release`. If cleanup remains unconfirmed, report the remaining state and keep the lease; do not claim verification complete or role readiness.
7. Stop. The coordinator verifies the content-addressed artifact and repository identity, closes the role, and advances automatically. After unanimous approval it harvests, delivery-checks, fast-forward pushes once, and retires owned worker and reviewer worktrees (`--keep manager`). After a blocked or failed run it harvests remaining worker commits when possible, then retires those children the same way. Attach-existing manager worktrees stay.
8. A parked manager may remain in its terminal. If the operator asks about progress, run `workflow status` for this workflow id and optionally `workflow artifact show`. Answer from that JSON only; do not change lifecycle state.
9. If the operator asks to keep only this manager or close the finished run, run `workflow harvest` then `workflow retire --keep manager` or `workflow retire --keep none` for this workflow id. Parent agents use the same commands with one or more root ids when `workflow cleanup --dry-run` reports `retire_recommended`. Do not ask child agents to close themselves. Harvest and retire are not substitutes for `complete`, `cancel`, or `proceed`.

When review requests changes, the coordinator returns the feedback artifact to the existing worker. The next worker readiness requires a new commit. A declared blocker closes the current role, cancels requested successors, and blocks the aggregate run instead of leaving the coordinator waiting. Queue wait parks the role until grant. The supervisor expires a lease only when its owner is dead. Manual `proceed`, `handoff`, and `advance` are operator recovery controls only.
