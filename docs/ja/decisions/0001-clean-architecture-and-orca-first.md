# ADR 0001: 明確な境界と最初のアダプターとしての Orca

[English](../../en/decisions/0001-clean-architecture-and-orca-first.md) | [日本語](0001-clean-architecture-and-orca-first.md)

## ステータス

採用

## コンテキスト

前身のツールでは、ターミナル制御、ワークフローポリシー、設定、issue 処理が混在していました。バージョン 1.0.0 では、今すぐ信頼できる Orca 実装が必要である一方、将来ほかの IDE へ進む現実的な道筋も残す必要があります。

## 決定

コアの状態とユースケースをアダプター非依存にします。Orca 固有のサブプロセスコマンドは `packages/orca` だけに置き、エントリポイントはその逆ではなく application service に依存します。バージョン 1.0.0 で実装するアダプターは Orca のみです。

## 結果

- 別の IDE に必要なのはアダプターであり、2つ目の CLI や queue ロジックの fork ではありません。
- Orca の変更は局所化されます。
- 抽象化はユースケースによって必要性が示されなければなりません。バージョン 1.0.0 では不要なアダプターを作りません。
