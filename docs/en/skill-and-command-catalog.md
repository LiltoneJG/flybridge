# Skill and command catalog

[English](skill-and-command-catalog.md) | [日本語](../ja/skill-and-command-catalog.md)

Flybridge ships only reusable public guidance. Organization and personal policies stay in external catalogs and are referenced through local JSONC configuration.

## Bundled guidance

| Path                                    | Purpose                                                                                                                                                                                                                                                                  |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `skills/resource-coordination/SKILL.md` | Acquire a named FIFO resource once, wait for a lease-id notification if needed, and hold the lease through cleanup confirmation before release                                                                                                                           |
| `skills/role-lifecycle/SKILL.md`        | For orchestrated roles, store artifacts and signal `role-ready`; queue wait is parking, not blocked. For a single role, verify, push once, report, and stop. The coordinator harvests, delivery-checks, fast-forward pushes an approved tip, and retires owned children. |

List the absolute path to `skills/` in `skills.sources` to discover bundled `SKILL.md` documents, or a glob such as `/path/to/flybridge/skills/*/SKILL.md`. External skill paths expand `~` and directory symbolic links.

## Agent-facing queue commands

| Command                                                      | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `flybridge doctor --mode orchestrated`                       | Validate state storage, role agents, skill paths, required commands, and the reachable Orca runtime before launch                                                                                                                                                                                                                                                                                                          |
| `flybridge workflow start --attach-existing`                 | Start a new agent in an existing Orca worktree without creating or deleting it. Queue observer follows `queue.observer` unless `--queue-observer` / `--no-queue-observer` is passed.                                                                                                                                                                                                                                       |
| `flybridge workflow start --batch`                           | Sequentially attach existing worktrees from a JSON array and summarize successes and failures. Prints JSONL per item then `{ok, failed, results[]}`. Each item needs `path` (or `repository`), `objective` or `objective_file`, optional `mode`/`name`/`issue`. Observer rule matches `--attach-existing`.                                                                                                                 |
| `flybridge workflow observe <workflow-id>`                   | Open a visible queue observer for one running workflow with a live owner terminal; otherwise resume first                                                                                                                                                                                                                                                                                                                  |
| `flybridge workflow cleanup`                                 | Dry-run recoverable workflow ownership (same as `--dry-run`). Finished roots with leftover owned children set `retire_recommended`. `--apply` needs `--older-than-seconds`; `--force-age` is implied.                                                                                                                                                                                                                      |
| `flybridge workflow harvest [--dry-run]`                     | Copy worker commits into the finished manager worktree. Accepts one or more root, child, or run ids. Does not close terminals or delete worktrees.                                                                                                                                                                                                                                                                         |
| `flybridge workflow delivery-check <id>...`                  | Verify before push that manager HEAD exactly matches the SHA approved by every local reviewer.                                                                                                                                                                                                                                                                                                                             |
| `flybridge workflow retire --keep manager\|none [--dry-run]` | Harvest, then close owned worker/reviewer terminals and worktrees. `--keep manager` retains the manager; `--keep none` also closes manager terminals and deletes a manager worktree only when Flybridge owns it. Attach-existing manager worktrees are never removed.                                                                                                                                                      |
| `flybridge workflow artifact put`                            | Atomically store an orchestrated role's bounded plan, verification, or review artifact under `state_dir`                                                                                                                                                                                                                                                                                                                   |
| `flybridge workflow artifact show` / `verify`                | Read or digest-verify a durable workflow artifact                                                                                                                                                                                                                                                                                                                                                                          |
| `flybridge workflow role-ready`                              | Signal verified orchestrated-role readiness without closing its terminal; reviewers use approved/changes-requested, and every orchestrated role may use `--outcome blocked`                                                                                                                                                                                                                                                |
| `flybridge workflow status`                                  | Report workflow and child records, orchestration run/review cycle, repository identities, artifact metadata, observer state, and read-only `progress`                                                                                                                                                                                                                                                                      |
| `flybridge board screen`                                     | List configured GitHub Project issues; optional `--board`, `--status`, `--priority`, `--assignee`, `--all-assignees`, `--with-refs`, `--path-prefix`, `--exclude-prefix`, `--exclude-name`. `--status` / `--priority` ignore spaces and case. Duplicate checkouts collapse before `--with-refs`.                                                                                                                           |
| `flybridge prs screen`                                       | List authored GitHub pull requests; optional `--author` (default `github.login`), repeatable `--state`, `--with-review-facts`. Thin rows include `base_ref_stale`. Does not join worktrees                                                                                                                                                                                                                                 |
| `flybridge prs refresh-base`                                 | PATCH a pull request so GitHub recomputes its base onto the current target-branch tip                                                                                                                                                                                                                                                                                                                                      |
| `flybridge inventory`                                        | Snapshot Orca worktree git facts and pull requests (open, plus bounded merged/closed/hinted); optional `--path-prefix`, `--exclude-prefix`, `--exclude-name`, `--no-github`, `--with-review-facts`. Config `reconcile.exclude_worktrees` and `github.skip_repositories` apply. Duplicate Orca cards for the same resolved checkout collapse to one row with `orca.aliases`. Transient GitHub 5xx is a warning, not exit 2. |
| `flybridge reconcile [--dry-run] [--no-github]`              | Reconcile durable worktree, git, and reference observations; dry-run reports planned changes. `reconcile.exclude_worktrees` is applied by default                                                                                                                                                                                                                                                                          |
| `flybridge worktree repository add\|remove`                  | Manage an explicit related-repository relation for an observed Orca worktree                                                                                                                                                                                                                                                                                                                                               |
| `flybridge queue acquire`                                    | Join a named FIFO queue once and receive a request or lease ID                                                                                                                                                                                                                                                                                                                                                             |
| `flybridge queue inspect`                                    | Operator/debug lookup of one owner-matched request                                                                                                                                                                                                                                                                                                                                                                         |
| `flybridge queue release`                                    | Release an owner-matched exact lease and promote the oldest waiter                                                                                                                                                                                                                                                                                                                                                         |
| `flybridge queue status`                                     | Read aggregate queue counts                                                                                                                                                                                                                                                                                                                                                                                                |
| `flybridge queue watch --notify-workflow`                    | Stream events and deliver a lease-id prompt after FIFO promotion                                                                                                                                                                                                                                                                                                                                                           |

Role prompts include acquire/release when `queue.resources` is non-empty. Waiting agents stop until the worktree observer sends a lease-id notification. They must not poll inspect or watch. An empty resource list injects no resource instructions. When its original agent terminal becomes invalid, a notifying observer closes its Flybridge-owned terminal without changing its request or lease. `workflow observe` refuses to open a replacement while that owner terminal is dead. `workflow resume` restores the observer when `queue.observer` is true. Queue cancellation and stale recovery are intentionally operator-only CLI actions.

## Operator guidance

| Command                    | Purpose                                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------------------ |
| `flybridge operator guide` | Validate and print the configured private Operator skill index without exposing document content |

The Operator is the workflow caller, not a workflow role. Read the indexed routing skill first and then the skills applicable to the requested operational task. Decide workflow-wide constraints once and pass roles the decision and its validity. Pass direct issue, pull-request, or review-comment URLs for facts that the responsible role must inspect. Do not complete or proceed while required verification evidence is missing, including requested proof and kicking hosted CI when a source asks for those, not code inspection alone. Hosted CI is complete once triggered; do not wait for its result. Obtain missing prerequisites or keep the role blocked.

## Autonomous and recovery lifecycle commands

| Command                                | Purpose                                                                                                                                          |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `flybridge workflow supervise`         | Durable coordinator loop. Normally created automatically in an Orca terminal by orchestrated start; `--once` is for diagnosis and replay testing |
| `flybridge workflow coordinator-retry` | Operator hot-upgrade/crash recovery: reset an eligible blocked/failed run and launch current coordinator code without changing role progress     |
| `flybridge workflow coordinator-close` | Operator fallback that closes a released coordinator tab when post-flush self-close did not complete                                             |
| `flybridge workflow proceed`           | Operator recovery only: record the handoff, complete the running source role, and advance                                                        |
| `flybridge workflow list`              | List workflows, optionally filtered by status                                                                                                    |
| `flybridge workflow link\|unlink`      | Manage explicit primary or related issue/PR references for a run or workflow step id                                                             |
| `flybridge workflow handoff`           | Recovery only: record the one-line successor summary while the source role is `running` or `completed`                                           |
| `flybridge workflow complete`          | Finish a running role and close its owned terminals. An orchestrated manager or worker is rejected until the successor handoff exists.           |
| `flybridge workflow advance`           | Recovery only: launch the next child after the predecessor is `completed` and the handoff exists                                                 |

Roles normally write their artifact and call `role-ready`; the coordinator verifies it and advances. A manager must leave the repository at its starting SHA. A worker must commit a change newer than its cycle start SHA. A reviewer records `approved` or `changes-requested`; requested changes return to the existing worker with the review artifact until the configured cycle limit. Role prompts forbid manual lifecycle commands. Operators use them only to recover a blocked or interrupted run from a terminal outside the role.

Artifacts are content-addressed as `state_dir/artifacts/workflows/<manager-id>/<kind>.<sha256>.md`, never in the implementation repository. Workflow identity has three distinct fields: `implementation_repository`, `runtime_repository_id`, and `start_sha`. The runtime ID selects the correct Orca repository for attached-root children; the other fields verify source repository and Git ancestry.

## Worktree inventory contract

Agents that need the merge-readiness *facts* for Orca workspaces must run `flybridge inventory` with the same `--config` used for other Flybridge commands. For review, comment, and thread bodies, pass `--with-review-facts`. The JSON document is the source of truth for collection. Do not write one-shot Python collectors or raw `gh api graphql` queries unless `flybridge inventory` itself failed. A non-zero exit after JSON output is a collection failure, not a mergeability verdict. The command reports facts only: it may include GitHub Actor `is_bot` on review authors, but it does not apply operator policy, interpret review comments as blockers, or decide whether a pull request is mergeable.

To join Project issues to local checkouts, run `flybridge board screen --with-refs`. That command intersects canonical GitHub issue URLs (Orca comments, same-repo linked issues, and issue body URLs) with GitHub development refs, including parent and submodule branch heads. Unmatched selected checkouts appear in `unmatched_worktrees`. It does not parse worktree directory names and does not decide whether work is unstarted.

Agents that need authored pull-request facts must run `flybridge prs screen` with the same `--config`. For review, comment, and thread bodies, pass `--with-review-facts`. Do not write one-shot collectors or raw `gh search` queries unless `flybridge prs screen` itself failed. The command does not join worktrees or emit mergeability verdicts.
